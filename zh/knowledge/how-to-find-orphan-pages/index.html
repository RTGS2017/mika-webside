如何发现孤立页面

孤立页是线上存在、却几乎没有内链可达路径的 URL——容易漏掉，也容易半途而废。

直接答案

孤立页面指站点上存在，但从你抓取到的其他页面出发没有（或几乎没有）内链的 URL。发现孤立页，需要对照多种 URL 来源：可点击链接的全站抓取、sitemap 成员、如有则用分析或日志落地页，以及 CMS / feed 导出。出现在链接图之外的页面需要决策——重新连接、合并或下线——而不是自动抬升。

孤立是发现与架构问题。它不证明页面「一定很差」，修好也不承诺排名。目标是让人与爬虫都能通过可抓取链接到达同一批有用内容。

为何重要

迁移、活动落地页、PDF 转 HTML，以及离开目录导航的 SKU，都会留下孤立页。没有入链时，这些 URL 依赖书签、广告或 sitemap 提示。公开的抓取说明强调：搜索系统主要通过跟随链接发现内容；sitemap 有帮助，但不能替代清晰结构。

在 B2B 站点上，孤立页常藏着安装说明、对比说明或区域变体——买家仍需要它们。断开连接会浪费编辑投入，也让审计失真：内容在，结构却看不见。

怎么检查

  1. 建立链接图抓取 — 从首页与关键枢纽出发，只收集可抓取的 HTML 链接。
  2. 收集候选 URL 集 — XML Sitemap、CMS 已发布导出，以及可选的日志 / 分析落地页。
  3. 做集合差 — 标记出现在 sitemap 或导出、却不在链接图中的 URL，作为孤立候选。
  4. 核对线上状态 — 确认 200 / 跳转 / 错误，记录规范目标与 noindex。已 404 的孤立是清理，不是加链任务。
  5. 按职责分类 — 保留（对买家有用）、合并（近重复）、删除（薄弱残留），每类保留样例 URL。
  6. 蓝图加链或下线 — 保留项从应归属的类目 / 产品 / 主题枢纽加语境内链；复审新抓取是否出现该 URL。

具体例子

某制造商在活动中发布详细选型指南。URL 仍在 sitemap 且可打开，但活动枢纽已下线，产品页也没有链过去。从导航抓取看不到它，只有 sitemap 列出。

诊断把它标为 SEO Health 的发现路径问题。蓝图可能从两处相关产品模板与应用枢纽加入「相关指南」链接；若已被更新手册取代，则重定向到新手册并从 sitemap 移除旧 URL。复审查入链与最终状态码。任何一步都不宣称排名变化——只恢复有意的路径。

Mika：健康 vs 增长

发现并重新连接孤立页，主要是 SEO Health：架构与抓取路径。写出从未存在过的指南，才是 SEO Growth。Mika 把二者分开，避免把「给残留加链」当成「覆盖尚未回答的需求」。

常见问题

孤立页会影响什么？

孤立页削弱有意的发现路径。沿内链前进的用户与爬虫可能永远到不了该页。有用的文档或产品变体可能长期曝光不足，而仅存在于 sitemap 或广告落地的 URL 仍占用注意力。审计也会更难：内容在，结构却假装它不在。

只出现在 XML Sitemap 里的页面算孤立页吗？

从链接图角度看，常常算。Sitemap 可以列出零入链的 URL。把「仅 sitemap」视为发现风险：要么从相关枢纽加有语境的内链，要么若不打算独立存在，就移出 sitemap 并下线或合并。

是不是每个孤立页都该补新内链？

不是。先判定页面职责。对能回答买家或支持需求的页面保留并链接；对近重复做规范或合并；对薄弱残留做 noindex 或删除。给一切都加链只会增加杂乱，并不能改善以人为本的覆盖。
