CORS 约束的是脚本读取另一个源，不是抓取

短答

CORS 是浏览器的一条规则，关于脚本是否可以读取来自另一个源的响应。

流程图从 JavaScript 发出跨源调用开始。有些请求直接继续，另一些先做 OPTIONS 预检，然后浏览器才查找 access-control 头。失败则走到错误。那是脚本在浏览器里的问题。爬虫获取你的 HTML 并不是那个脚本。SEO 健康不把 CORS 错误当作 robots.txt 规则，也不把宽松的 CORS 头当作索引某个 API 的邀请。

定义

robots.txt 和 X-Robots-Tag 告诉爬虫如何获取和索引一个 URL。CORS 告诉浏览器关于页面脚本的事。阻止其他站点的脚本读取你的 JSON，并不会阻止爬虫请求一个公开的 HTML URL；允许这种读取，也不会把 JSON 放进 sitemap。如果产品列表只存在于一次跨源调用之后，就发布一个包含该列表的 HTML URL。流程图是浏览器如何选择的地图。它不是本文让你抄到私有 API 上的配置。

抓取怎样遇到这条规则

把抓取规则放在 robots 和头里，CORS 只用于浏览器脚本可以读取什么。

不要因为一个小组件的 CORS 请求失败就 noindex 一个页面，也不要因为 CORS 允许就把 API URL 加进 sitemap。直接获取 HTML URL，看文档是否在那里。如果你设置的头挡住了字体或样式表这类公开资源，渲染仍然可能坏掉。那是资源问题，和 robots 分开。图中的错误框是脚本的错误，不是抓取状态。

要检查什么

  • 产品列表存在于一个 HTML URL 中
  • API URL 不在 sitemap 里
  • robots 规则写成 robots 规则，而不是 CORS
  • 字体和样式表没有被意外挡在你自己的页面之外
  • 不依赖脚本获取一条 HTML URL

一个结构示例

零件表由脚本从 API 主机加载。CORS 在某些浏览器里失败，团队把 API URL 加进了 sitemap。修复是发布包含该表的 /parts HTML，链接到它，并把 API 留在 sitemap 之外。API 上的 CORS 可以保持严格。流程图没有被抄成一项政策。

它不声称什么

CORS 设置不保证排名或引用。
