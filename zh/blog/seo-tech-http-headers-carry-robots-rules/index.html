短答

HTTP 头可以为这次响应携带 robots 指令，这对不是 HTML 的文件很重要。

照片里是 Tim Berners-Lee 在讲话，附近还有另一位人和一台笔记本电脑。这是 HTTP 头页面上、与早期网页有关的一个人的照片。它不是头字段的示意图，不是本站用作背书的肖像，也不是关于任何爬虫的证据。本文的规则是头字段本身。

定义

HTML 可以使用 meta robots 元素。PDF 或其他非 HTML 响应不能。该响应上的 X-Robots-Tag 头可以对该 URL 说 noindex 或 nofollow。与 meta 元素矛盾的头就是两条规则。只保留一条，并记下你打算用的是哪一条。头很容易被漏掉，因为它不出现在人阅读的正文里。打印响应头的一次获取才是检查。照片里没有这个头。

抓取怎样遇到这条规则

当 URL 不是 HTML 时，在响应头里发送 robots 指令，并且不要和 HTML meta 矛盾。

获取 URL，先读状态和头，再读正文。如果页面本意是被索引，公开规格上的 noindex 头就是健康发现。私有文件上的 noindex 头可以是有意的。要写明是哪一种。不要把照片里的人名写进头里，也不要把照片当成资质。

要检查什么

  • 非 HTML URL 检查了 X-Robots-Tag
  • HTML meta 和头不冲突
  • 公开文档没有被意外加上 noindex
  • 应该排除的私有文件是有意标记的
  • 获取一份 PDF 时能看见响应头

一个结构示例

产品 PDF 返回 200，没有 X-Robots-Tag，团队以为 HTML 外壳里的 meta 标签会作用到文件上。并不会。修复是在 PDF 响应上设置他们真正想要的头，并重新获取一个文件。肖像留在来源页上。它不是头的一部分。

它不声称什么

robots 头不保证排名或引用。
