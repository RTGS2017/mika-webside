多语言站点地图只列出已经存在的 URL

多语言 XML 站点地图列出你希望被找到的规范 URL，包括你真正发布的每种语言。它可以帮助抓取程序发现这些 URL。它不会写翻译、不会修好 hreflang，也不保证被索引。

定义

在本站，英文 URL 在根目录，中文 URL 在 /zh/。两者都可以列出。每个条目都应是规范 URL，而不是参数副本、重定向或薄壳。对照关系可以写在站点地图里，也可以写在页面的 hreflang 里。页面上的标记仍然必须一致。x-default 指向英文。这套结构里没有 /en/ 前缀。

短答

多语言 XML 站点地图列出你希望被找到的规范 URL，包括你真正发布的每种语言。它可以帮助抓取程序发现这些 URL。它不会写翻译、不会修好 hreflang，也不保证被索引。

哪些字段必须说同一件事

在一次获取能返回标题和主要文字之后，再加入 URL。把你真正提供的语言对照页也包括进去。如果中文页仍只是复制的标题，就不要用站点地图假装市场已经覆盖。在页面回答问题之前，问题覆盖仍然是未回答。

页面上的问题

站点地图是覆盖和新鲜度清单。它不适合用来藏孤立页面：那些 URL 还需要带描述性锚文本的内部链接。站点地图里的坏地址，和正文里的坏链接一样浪费信任。

随页面一起走的信号

索引不一致应作为审计发现：列出了但不可索引，或可索引却没有列出。发现不是分数，清掉它也不是排名承诺。在文件和页面一致之后再复审。

站点地图是文档清单，不是文档的替代品。 Mika Visibility 要求每种已发布的语言保留同一套公司名、产品名、规格和应用，同时允许该市场的问题有真正的深度。英语在站点根目录，中文在 /zh/，不要增加 /en/ 前缀。hreflang 使用 en、zh-Hans，以及指向英文 URL 的 x-default。健康分数不会自动变成增长分数。

要检查什么

  • 只列出能返回预期文字的规范 URL。
  • 列入真实的 /zh/ URL，而不是 /en/ 副本。
  • 让站点地图中的对照关系与页面 hreflang 一致。
  • 每个列出的 URL 也要有内部链接。

它不声称什么

完整的多语言站点地图不保证被索引、排名或 AI 引用。Mika 阅读站点地图是为了看覆盖和不一致，不是为了承诺结果。

一个结构示例

这是教学示例，不是抓取日志。站点地图列出一个返回 404 的中文产品 URL，真正的页面却在更深一层的路径上。修复是列出能返回规格的规范 URL，对齐 hreflang，然后复审。不编造索引率。
