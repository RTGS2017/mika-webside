首次输入延迟已不再是响应性的现行定义

短答

首次输入延迟是较旧的响应性标记，它只看第一次输入。

交互到下次绘制在 Core Web Vitals 中取代了它，因为目录上较慢的可能是后来的输入。把首次输入延迟和首次绘制、可交互时间标在一起的轨迹是一张历史示意图。它解释旧标记。它不是继续把旧标记当作现行定义来报告的许可，也不是任何网站的测量。

定义

B2B 页面上的第一次输入常常没有代表性：页面还忙时点了一下标志区域，或者轨迹期间根本没有输入。一分钟后的筛选点击，首次输入延迟看不见。所以健康检查如果仍然只谈第一次输入，描述的是过时定义。SEO 健康应该写明它使用的定义。

健康检查里怎么使用这个定义

如果报告仍写首次输入延迟，应标明那是旧定义，并另行查看后来的交互。

本页的轨迹有用，是因为它在一次加载上标出多个标记。这些标记不能互换。可交互时间不等于输入延迟，首次绘制也不是这两者。把标签混在一起，会写出没人能修的记录。本文不会从图上读一个数字再安到某家公司身上。

要检查什么

  • 当前记录是否仍把首次输入延迟当作现行定义
  • 旧标记看不见的后来交互
  • 首次绘制、可交互时间和输入延迟保持分开标注
  • 现在要紧的交互的一条样例 URL
  • 没有从历史示意图上抄数字

一个结构示例

一份旧的仪表板导出仍列出首页的首次输入延迟，而首页很少有第一次输入，对分类模板上的分面点击却只字不提。健康方面的更新是：不再把那一行当作现行的响应性检查，改为抽样分面交互。

它不声称什么

停用旧标记不保证排名或引用。

Mika Visibility 把它归到哪里

Mika Visibility 把它归在 SEO 健康：线上站点在技术上是否准备好被发现和理解。SEO 增长仍是关于覆盖和意图的另一个问题。GEO 健康与 GEO 增长保持各自的尺度。一条加载或响应性记录不会自动变成增长分数，也没有混合总分。

轨迹区分了旧标记和相邻标记，因此本页可以解释这次替换，而不编造延迟。
