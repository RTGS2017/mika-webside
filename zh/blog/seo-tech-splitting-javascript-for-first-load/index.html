短答

单个巨大的 JavaScript 代码块让首次加载下载并解析的东西超过屏幕所需。

网络面板显示的就是那一个文件。按路由拆分可以把产品页的额外工具留在另一个代码块。健康条件是产品名和链接在 HTML 里，而不只在被拆出去的代码块里。更小的首个代码块如果仍然给一个空壳注水，那是渲染上的失误。

定义

面板截图是一次下载的工具视图。它不是预算，也不是分数。团队不应从某次演讲里抄一个字节上限并称之为政策。本地问题是这个模板的首次响应是否包含它的文字，以及未使用的代码是否搭车而来。

渲染对爬虫意味着什么变化

只有在 HTML 包含主要文字和链接之后，才把未使用的代码拆出首个代码块。

路由级拆分如果把规格表的唯一副本也拆走，抓取比较就会失败。把表格放进服务器 HTML，并拆走绘图库。再审计时阅读一条 URL 的源代码和网络列表。

要检查什么

  • 主要文字在 HTML 里，而不只在代码块里
  • 其他屏幕的库被拆走
  • 拆分之后检查了源代码
  • 一条目录 URL 作为样例
  • 没有把字节上限口号当作政策

一个结构示例

目录条目下载的代码块里有三维查看器、博客编辑器和产品事实。事实移进 HTML。查看器和编辑器移到使用它们的屏幕才加载的代码块。首次网络列表显示更小的代码块，以及已经点名产品的文档。

它不声称什么

更小的代码块不保证排名或引用。

Mika Visibility 把它归到哪里

Mika Visibility 把渲染当作 SEO 健康问题：当模板依赖 JavaScript 时，重要 HTML 能否在有脚本和无脚本两种情况下被获取并比较。这种比较不是 GEO 审计，也不是市场覆盖计划。发现要附在样例 URL 上。模板改完之后的再审计，用来确认修复。

网络面板显示一个代码块，因此文章可以讨论还有什么不应该在它里面。
