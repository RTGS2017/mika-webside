短答

后退-前进缓存恢复访客已经看过的页面，而不是从头加载。

开发者工具可以说页面被恢复了，或为什么没有。unload 处理函数、某些 cache-control 值，以及某些连接类型，是页面不合格的典型原因。SEO 健康在模板上记下这些阻碍，因为每次点后退都完整重新加载，会重复首次加载的代价。面板截图是工具示意，不是本站的结果。

定义

这种缓存是浏览器对历史导航的行为。它不是你用很长的 max-age 设置的 HTTP 缓存项，也不是 CDN。把三者弄混会导致改错响应头。审计点名失败的是哪一种机制。

渲染对爬虫意味着什么变化

在后退-前进面板中检查一条样例 URL，去掉仅因习惯而存在的 unload 处理函数或响应头。

绝不应被恢复的页面，例如一次性的付款确认，可以有意退出。产品页通常不应该退出。记录应该写明模板属于哪一种。合格与否不会索引页面，也不会给它排名。

要检查什么

  • 应该能恢复的模板上的 unload 处理函数
  • 意外阻止恢复的 cache-control 值
  • 有意退出的付款或其他页面
  • 在面板中检查的一条产品 URL
  • 该机制没有与 HTTP 缓存或 CDN 混淆

一个结构示例

每个模板都注册了一个旧分析片段留下的 unload 处理函数。后退-前进面板说产品 URL 不合格。去掉处理函数后产品页变为合格。付款确认页保留自己的退出。不附加分数。

它不声称什么

后退-前进缓存的合格不保证排名或引用。
