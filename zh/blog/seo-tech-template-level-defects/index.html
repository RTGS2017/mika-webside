短答

模板级缺陷是在该类型的每个 URL 上重复的一条规则。

图显示一份数据列表和一个带占位符的模板，经处理后变成两份完成的页面。如果该模板省略了 canonical 元素，两份页面都省略它。在不控制模板的 CMS 里改一个页面，会被覆盖，或让其他页面仍然是坏的。SEO 健康优先处理模板。样例 URL 证明这种模式。它不是唯一要紧的页面，也不是带指标的案例。

定义

Mika Visibility 的爬虫说明要求在逐页改文案之前优先处理模板级缺陷，并附上原因、做法，以及忽略该发现会怎样。本文遵循这个顺序。模板健康之后，仅在一个 URL 上写错的文案仍然可以是页面发现。

结构如何承载发现

抽样该类型的一条 URL，修好共享版式，并重新获取该 URL 和同类型的另一条。

对产品正确、对文档错误的模板是两个模板。如果 URL 规则不同，不要用复制产品 canonical 逻辑来“修好”文档页。用类型名称写下发现。只打开原始样例的再审计，可能漏掉仍然发出该缺陷的第二种版式。

要检查什么

  • 缺陷在同类型的第二条 URL 上重复
  • 修复做在共享版式里
  • 在复制同一修复之前检查了另一种类型
  • 发布后的重新获取
  • 文案修改没有被用来代替版式

一个结构示例

每个产品 URL 都缺少指向自身的 canonical，因为版式从未打印它。样例是一条阀门 URL。修复在版式里。发布后再获取第二条阀门 URL，以确认这一类变了。描述的词语从来不是这个缺陷。

它不声称什么

修好模板不保证排名或引用。

Mika Visibility 把它归到哪里

Mika Visibility 把架构读成 SEO 健康：重要模板是否位于爬虫能从枢纽跟着走的路径上。深度和孤立页是结构。没被回答的买家问题是 SEO 增长。整齐的树不能保证页面容易被引用，那是 GEO 的质量，不是引用承诺。
