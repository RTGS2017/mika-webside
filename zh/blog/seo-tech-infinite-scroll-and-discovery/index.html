短答

无限滚动在访客移动时把后面的条目装进当前页，除非你另外添加，这些条目没有自己的 URL。

照片显示的是人的手势。抓取问题在那张照片里看不见：爬虫不会滚动。如果下一批产品只在交叉观察器触发后才存在，它们就不在被获取的 HTML 里。SEO 健康要求你希望被发现的每一组都有一个被链接的 URL。

定义

为人保留滚动、同时在 HTML 里渲染页面链接的混合做法可以同时满足两边。只用 history.pushState 更新地址栏、而该地址没有服务器响应的混合做法，会造出一个重新加载后仍是第 1 页的 URL。那是假地址。获取它看看。

抓取怎样遇到这条规则

为滚动本来会藏起的集合提供可抓取的分页 URL，并确保这些 URL 返回它们自己的条目。

不要因为条目在演示里出现过，就认为滚动加载的条目已被索引。浏览器会话中的出现不是一次获取。样例是用普通 HTTP GET 请求的第二页 URL，并检查正文里有没有那些条目。

要检查什么

  • 后面的条目不在第一份 HTML 响应里
  • 对普通 GET 返回这些条目的分页 URL
  • 重新加载后变成另一页的历史 URL
  • 指向下一组的 HTML 锚点
  • 记录中有一次第二页获取

一个结构示例

零件列表在 /parts 上永远滚动。第二屏零件没有地址。增加返回这些行的 /parts?page=2，并在 HTML 里链向它，就创造了路径。滚动可以留下来作为一种便利，去请求同一个 URL。

它不声称什么

在滚动旁边添加分页 URL 不保证排名或引用。
