短答

Service Worker 位于浏览器和网络之间，可以用缓存作答。规范 URL 仍必须向不执行该 worker 的一次获取返回 HTML 规格。缓存不是记录文档。

定义

应用壳有时发送一份空 HTML，再用脚本或 worker 填满。如果一次基本获取只收到壳，这个 URL 就还不是关于产品的文档。SEO 健康问的是响应里有什么。已经打开过页面的用户仍可以保留离线支持。操作范围不应只存在于那里。

页面上怎么出现

用不安装该 worker 的客户端获取规范 URL。读 HTML。如果范围缺失，就把它写进服务器或静态 HTML。检查 worker 不会在你改正文档之后仍缓存过期的 noindex 或旧价格。然后重新获取。

要检查什么

  • 在没有 Service Worker 的情况下获取并读 HTML。
  • 把规格放进该响应。
  • 不要缓存过期的 robots 指令。
  • 壳改完之后复审。

一个结构示例

目录路由返回一个空的应用壳。worker 稍后为回访用户绘出阀门范围。第一次获取永远看不到范围。修复是把范围放进 HTML 响应，并让 worker 缓存该响应。不暗示任何应用商店排名。

它不声称什么

正确的 Service Worker 设置不保证排名或 AI 引用。
