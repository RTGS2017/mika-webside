短答

关键 CSS 是绘制首屏所需的那一部分规则，有时内联在头部。

样式表的其余部分可以不阻挡这次首次绘制而加载。如果把每条规则都内联，HTML 会变重，而且从未真正选出“关键”子集。溢出屏幕的图是布局装不下的画面，这也是人们抽取首屏规则的一个原因。它不是测量。

定义

抽取可以对稳定模板手工完成，也可以由经过复查的构建步骤完成。未经复查的抽取器可能内联页面并不处于的状态的规则，或漏掉防止布局跳动的规则。SEO 健康把结果当作要在样例 URL 上检查的标记：首屏是否有样式，HTML 是否没有扛着整个设计系统。

渲染对爬虫意味着什么变化

只内联首屏规则，并在样例 URL 上确认完整样式表没有同时在头部重复一份。

完整样式表到达后发生布局跳动，说明关键子集不完整。这是 CSS 拆分引起的、形态像 CLS 的缺陷，应该照此记录。修复是把缺失的规则放进子集，而不是不看情况就放弃这个想法、重新用整个文件去阻挡。

要检查什么

  • 内联规则匹配模板的首屏
  • 完整样式表没有同时被复制进头部
  • 完整样式表到达时没有布局跳动
  • 产品 URL 和首页 URL 分开检查
  • 抽取器的输出经过复查而不是盲目信任

一个结构示例

构建把首页主视觉规则内联进每个产品页，产品标题用的是稍后才到的另一套规则，于是标题跳动。健康记录写的是子集跟着首页走，而不是产品模板。每个模板需要自己的首屏子集，或者都不要。

它不声称什么

内联子集不保证排名或引用。
