短答

沉重的 JavaScript 可以推迟交互，但 HTML 仍然必须包含主要文字。

标出脚本执行很长的实验室审计是渲染记录。它不是页面缺少内容的证明，也不是可以公布的分数。如果查看源代码是一个壳，即使脚本很小，健康发现也是这个壳。如果查看源代码是完整的而脚本很大，发现就是脚本对交互的代价。

定义

代码拆分如果让首次响应更小、又不拿走文档里的文字，就属于这条记录。如果拆分把文字留在爬虫从不当作文档的代码块里，并不能解决发现。SEO 健康在样例 URL 上把这两种结果分开。

渲染对爬虫意味着什么变化

先检查原始 HTML 里有没有主要文字，如果文字已经在，再把脚本代价另记一行。

第三方标签是模板首次绘制并不需要的重量的常见来源。它们作为自己的加载顺序问题来讨论。审计不应该建议删掉产品文案来“节省 JavaScript”。文案是文档。脚本是额外的东西。

要检查什么

  • 原始 HTML 中有主要文字
  • 文字存在时，脚本代价只作为第二行记录
  • 藏着文字唯一副本的代码块
  • 一条配置器或产品 URL 作为样例
  • 没有从实验室图片抄来的分数

一个结构示例

配置器的 HTML 包含产品名和选项标签，一个很大的可视化库为三维视图而加载。健康记录肯定这份 HTML，并把库记为该 URL 上的交互代价。另一个模板把选项标签只放在库里，则是不同的、更严重的发现。

它不声称什么

减轻脚本重量不保证排名或引用。
