短答

网络爬虫从队列中取出 URL，获取它们，并保存它能够读到的响应。

图显示的就是这条流水线：地址队列、获取器和存储。它是部件的地图，不是排名系统，也不是本站的一次追踪。SEO 健康问的是你的重要 URL 能否进入这种流水线：返回文档的状态、允许获取的 robots 规则，以及一开始就把 URL 放进队列的链接或 sitemap 条目。

定义

获取不等于理解。被存下来的响应如果是壳、403 或 500，那就是被存下来的失败。架构图不保证每个方框都会对每个站点运行，本文也不编造抓取预算或覆盖百分比。实用的读法是样例 URL：一次干净的获取返回什么，以及哪个页面链接到了它。

抓取怎样遇到这条规则

给重要文档一个获取器可以请求的 URL，以及一条能把它放进队列的链接。

sitemap 可以把 URL 加进工作列表。它不能代替链接，也不能修好 500。保存响应是爬虫的事。你的事是让响应就是那份文档。模板改完之后重新获取样例，而不是假定图里的存储方框会自己更新。

要检查什么

  • 返回文档的一条样例 URL
  • 能把它放进队列的链接或 sitemap 条目
  • 允许该次获取的 robots 规则
  • 失败被记成状态码，而不是缺主题
  • 模板更改后的重新获取

一个结构示例

一份新规格只存在于一个把它载入当前页面的按钮里。没有 URL 被获取，队列里也就放不下它。修复是发布一个返回该规格的 URL，并从产品页链接它。架构图仍然是一张总图。它不是那条产品 URL 的日志。

它不声称什么

可被获取不保证排名或引用。
