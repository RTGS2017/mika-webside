短答

会渲染的爬虫获取 URL、渲染它，并从渲染结果中抽出链接。

图显示的是这个循环：队列、获取、处理、渲染、链接回到队列。它描述的是有能力的爬虫，不是每一个爬虫，也不保证你的 URL 会很快被渲染甚至一定被渲染。SEO 健康仍然希望重要文字和链接在第一份 HTML 里，这样发现就不依赖渲染队列。

定义

这张图是对某个系统流水线的公开说明。它不是时间表，也不是任何站点被渲染频率的测量。把图片贴进报告并不能证明你的壳被渲染了。应该在一条商业样例 URL 上比较原始 HTML 和渲染后的 HTML。

抓取怎样遇到这条规则

把主要链接放进第一份 HTML，并在依赖渲染队列之前抽样比较原始 HTML 与渲染后的 HTML。

只在渲染页面里点击之后才出现的链接，可能永远进不了队列。即使爬虫会渲染，渲染量也是有限的。要经过很长的客户端交互才显示产品的模板，即使世上存在某种渲染，也是健康缺陷。

要检查什么

  • 原始 HTML 中有产品链接
  • 在一条商业 URL 上比较原始与渲染结果
  • 要点击才存在的链接
  • 不假设每个爬虫都运行图中的流水线
  • 模板更改后对源代码的再审计

一个结构示例

分类网格的链接在客户端筛选运行之后才创建。原始 HTML 没有产品锚点。图中的渲染步骤也许最终能看见它们，也可能不会很快。修复是把产品锚点写进 HTML。筛选仍然可以为人而运行。

它不声称什么

渲染流水线不保证排名、索引或引用。

Mika Visibility 把它归到哪里

Mika Visibility 把可抓取性放在 SEO 健康：robots 规则、状态码，以及爬虫能跟着走的路径。断开的路径和被挡住的模板是健康发现。缺主题不是。GEO 仍然依赖爬虫真正能到达的页面，但到得了并不等于替买家写好了答案。
