短答

长页面可以推迟后面区块的绘制工作，而不把这些区块从 HTML 里删掉。

content-visibility 一类的技术告诉浏览器可以跳过屏幕外区块的布局。这是渲染性能上的选择。它不是只在脚本发现滚动时才加载下一段产品的理由。SEO 健康仍然要问 HTML 里有没有文字和链接。

定义

把长页面拆成区块的示意图说的是控制工作量，不是无限滚动。首屏以下的规格章节可以留在文档里，布局成本仍然更低。如果章节要等交叉观察器触发才出现在 HTML 里，爬虫可能永远不会去请求它。这是两种机制，审计里不应写成同一句话。

渲染对爬虫意味着什么变化

即使后面区块的布局工作被推迟，也要确认它们在初始 HTML 里。

既使用渲染提示、又在响应里保留真实标题和表格的模板，与用户滚动时才从 API 取每一章的模板，健康状态不同。前者可以是性能记录。后者是抓取路径记录。如果不确定上线的是哪一种，就用有脚本和无脚本各抽样一次。

要检查什么

  • 屏幕外区块是否存在于第一份 HTML 响应
  • 指向这些区块的链接是否是锚点元素
  • 渲染提示没有被用来代替分页 URL
  • 一条长 URL 在有脚本和无脚本下都被检查
  • 布局成本和缺少 HTML 分成两条记录

一个结构示例

一份机械手册在一个 URL 里有二十个章节。团队加上渲染包含，让屏幕外的表格不必一次全部布局。HTML 仍然包含每一章。健康检查能通过“文字是否在文档里”这个问题，并可以另外记下布局成本。如果把章节换成滚动才加载的片段，第一个问题就会失败。

它不声称什么

推迟布局工作不保证排名或引用。
