短答

分页把长列表拆成若干 URL，其 HTML 包含该页的条目和指向相邻页的链接。

只把下一批条目取进同一个 URL 的控件不是分页。它是一份假装成许多份的文档，或藏在一份文档后面的许多条目。SEO 健康希望应该被发现的条目位于可获取的 URL。页面链接图显示的就是这种模式：分开的页面，而不是一段不断变长的滚动。

定义

如果每一页有你打算保留的不同条目集合，它应该把 canonical 指向自己，而不是全部指向第 1 页，否则后面的页面会告诉爬虫它们是第一页的重复。内链应该把下一页作为锚点，而不是只有一个运行脚本的按钮。全部查看的 URL 可以存在，如果它真的是你能够提供的一份文档，而不是把每一行都装进一个 DOM 的陷阱。

结构如何承载发现

给每一页自己的 URL、HTML 里自己的条目，以及指向下一页的锚点。

rel-next 和 rel-prev 曾经是常见提示。爬虫是否使用它们不是健康检查的核心。核心是可抓取的链接和诚实的 canonical。不要把第一页之后的每一页都 noindex，除非你决定那些条目不需要被发现，否则就不要对它们没被发现感到意外。

要检查什么

  • 每一页的条目存在于该 URL 的 HTML 中
  • 指向相邻页的锚点
  • 条目集合不同时使用指向自身的 canonical
  • 没有因习惯对后面的页面使用 noindex
  • 在第 1 页和第 2 页检查的一个系列

一个结构示例

目录的“下一页”控件用脚本替换网格，从不改变 URL。第 2 页的产品没有地址。修复是增加 /catalog?page=2，HTML 里有这些产品，canonical 指向该 URL，并从第 1 页放一个锚点。与分页组合的筛选仍然需要分面说明里的规则，否则 page 参数会把陷阱乘开。

它不声称什么

真实的分页 URL 不保证排名或引用。
