短答

对主视觉图片做懒加载，会推迟对那个常常决定最大内容绘制的元素的请求。

对比图说的是不同懒加载行为拉了多少图片数据，不是分数。健康要点更窄：如果最大元素被推迟，它的请求就不能随文档开始。SEO 健康在模板上标记这种模式。它不为图中的示例站点公布绘制时间。

定义

一些库和原生懒加载都会等到图片靠近视口。这种等待对首屏以下有帮助，对首屏有害。模板可以按位置同时使用两种行为。一个总是设置懒加载的辅助函数，就是主视觉被卷进去的方式。

渲染对爬虫意味着什么变化

去掉占据首屏的那张图的懒加载，其他图片可以保留。

当主视觉 URL 在头部就已经知道时，预加载可以是后续手段，但预加载不能成为同一张图仍保留 loading=lazy 的借口。两个提示是矛盾的。审计应该展示标记，而不是关于速度的口号。属性去掉之后，检查一条 URL 的原始 HTML，确认组件包装没有把它加回去。

要检查什么

  • 首屏最大图片上的 loading=lazy
  • 无法区分主视觉和网格的组件默认值
  • 同一 URL 上互相冲突的预加载和懒加载提示
  • 模板更改后的原始 HTML
  • 没有从图中编造绘制时间
