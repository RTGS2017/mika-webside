短答

stale-while-revalidate 允许缓存在获取更新的响应时，先提供一次已存储的响应。

图显示的就是这个顺序。过期之后的一次请求，访客可能看到上一份 HTML 或资源。这可以让重复访问变快，也可能让刚改过的价格或规格多显示一次。SEO 健康问的是模板能否容忍那一次陈旧响应。

定义

这条指令不能代替正确的规范 URL，也不能修复软 404。它只改变重新验证期间显示哪一份已存储的字节。用在个性化页面上时，如果缓存是共享的，可能把一个用户的陈旧页面漏给另一个用户。公开文档才是通常的候选。

渲染对爬虫意味着什么变化

仅当一次陈旧视图可以接受时，才在公开资源或公开 HTML 上使用这条指令。

刚刚为安全而改正的规格是糟糕的候选：多出来的那次陈旧视图是错误的文档。标志文件是合适的候选。审计应该点名响应，而不是因为一篇性能文章提到了它，就在整个主机上启用这条指令。

要检查什么

  • 公开资源与个性化 HTML
  • 安全关键文字被排除在额外的陈旧视图之外
  • 没有因习惯把指令用到整个主机
  • 一条产品 URL 和一条私有 URL 的比较
  • 不声称该指令能修复索引

一个结构示例

全局头部给每个响应都设置了 stale-while-revalidate，包括购物车和刚更新的压力等级。健康改动是从个性化和安全关键的 HTML 上去掉它，并留在带哈希的图片上。一条产品 URL 和购物车 URL 显示这种对照。
