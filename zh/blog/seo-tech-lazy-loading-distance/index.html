懒加载是距离上的选择，不是每张图的默认值

懒加载推迟的是仍然远离视口的图片。

短答

懒加载推迟的是仍然远离视口的图片。

距离是一个阈值，不是关于所有图片的道德规则。首屏里的图片可能就是最大绘制的候选，推迟它就会推迟那次绘制。远在下方的相关产品图可以等待。SEO 健康在模板上把这两个位置分开。

定义

图显示浏览器开始加载懒加载图片的距离会随时间变化，团队不应把它背成排名杠杆。对一个站点要紧的是哪些图片带了 loading 属性、它们位于哪里。阈值图是浏览器行为的定义。它不是对 Mika、某位客户或本营销站的测量。

渲染对爬虫意味着什么变化

不要对首屏里最大的那张图使用懒加载。

首屏以下的图库、文档缩略图和页脚里重复的标志，是普通的懒加载候选。产品主视觉、手册里的第一张图，以及作为 LCP 元素的图片则不是。给每个图片标签都加上 loading=lazy 的模板默认值是健康缺陷，尽管这个属性是合法 HTML。先改默认值，再审计一条产品 URL 和一条文章 URL。

要检查什么

  • 首屏图片上的 loading 属性
  • 模板下方可以等待的图片
  • 把每张图都标成懒加载的 CMS 或组件默认值
  • 改完之后的一条产品 URL 和一条文章 URL
  • 不声称某个像素距离是排名规则

一个结构示例

CMS 预设给每张图都做懒加载，包括铺满首屏的分类横幅。横幅的请求要等布局发现它很近才开始。从这一张模板图片上去掉该属性，请求就可以随文档开始。预设可以留给下面的缩略图网格。

它不声称什么

正确放置懒加载不保证排名或引用。

Mika Visibility 把它归到哪里

Mika Visibility 把渲染当作 SEO 健康问题：当模板依赖 JavaScript 时，重要 HTML 能否在有脚本和无脚本两种情况下被获取并比较。这种比较不是 GEO 审计，也不是市场覆盖计划。发现要附在样例 URL 上。模板改完之后的再审计，用来确认修复。

图解释的是距离阈值，因此文章可以拒绝“每张图都同一属性”的默认值。
