短答

查询字符串是 URL 中问号之后的部分，它可以为同一文档制造一个新 URL。

选择真实 SKU 的参数是身份的一部分。只用于排序、跟踪活动或保存会话的参数通常不是。SEO 健康希望文档有一个规范 URL，并且内链一致地指向它。sitemap 应该列出那个 URL，而不是每一种偶然组合。

定义

当重复页必须仍可访问时，canonical 元素用来声明首选 URL。如果重复页不必存在，重定向更好。留在内链上的跟踪参数是模板缺陷：站点在链接到自己的重复页。

这如何影响可索引的 URL

把每个参数分成身份或重复，并让 canonical 和内链指向首选 URL。

排序和视图模式参数是目录上常见的重复页工厂。如果它们必须为人而存在，除非排序视图真的是你打算索引的另一份文档，否则 canonical 不应包含它们。查询里的会话标识更糟，因为它们为每次访问创建一个 URL。把它们从链接里去掉。

要检查什么

  • 真正的身份参数与排序、跟踪或会话参数
  • 追加跟踪参数的内链
  • 去掉重复参数的 canonical 目标
  • 没有偶然查询的 sitemap URL
  • 显示重复形式和首选形式的一对样例 URL

一个结构示例

产品链接即使在内部导航也追加 ?utm_source=footer，于是每次页脚点击都是一个新 URL。健康修复是从内部锚点去掉跟踪参数，并对仍然从外部进来的那些做规范链接。不带查询的产品路径才是 sitemap URL。

它不声称什么

清理查询重复页不保证排名或引用。

Mika Visibility 把它归到哪里

Mika Visibility 把首选 URL 当作 SEO 健康信号。规范链接、重复页和 sitemap 不一致会连同样例 URL 一起记录。它们不预测排名。SEO 增长问的是这条首选 URL 是否真的覆盖了某个意图。这些问题保持在不同的尺度上。
