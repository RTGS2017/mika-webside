深度审计先看整站系统，再诊断，然后才写蓝图

路径是先审计，再诊断，然后蓝图，站点不会被收成一个分数。

定义

路径是先审计，再诊断，然后蓝图，深度审计把站点看成一个系统，而不是一个分数。它会先走过页面、结构、主题、实体、问题和证据，然后才写蓝图。发现按规则归组，并附上示例 URL，这样诊断能解释模式，蓝图能写出下一步。

短答

诊断放在审计和蓝图之间，因为一堆 URL 还不是计划。如果页面存在渲染，就把健康、可回答性和可访问性分成不同列，优先处理模板级缺陷，对照 JavaScript 与无 JavaScript 的结果，并写上原因、处理方式，以及忽略时会怎样。

要检查什么

  • 写蓝图之前先走查页面
  • 按同一规则归组发现
  • 发现旁边保留示例 URL
  • 诊断之后再写蓝图

它不声称什么

蓝图写完，并不保证随后的优化会带来搜索位置或引用。即便写明原因、处理方式以及忽略时会怎样，仍然不保证商业上的结果。

一个结构示例

如果许多产品模板都缺少直接答案，审计会把这些 URL 归到同一条规则下，而不是把每个 URL 当成单独的谜题。诊断解释这个共同缺陷，蓝图则针对模板来写，并保留示例 URL，方便以后核对。
