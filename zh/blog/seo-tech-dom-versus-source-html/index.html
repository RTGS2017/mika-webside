短答

DOM 是浏览器建起的元素树。源代码 HTML 是这棵树被改动之前，一次获取所返回的文字。

图画出了一棵小树：document、html、head、一个 title、body、一个 h1，以及一个带 href 的链接，各自有示例文字，例如标题和链接文字。这张图是一份已解析文档的形状。它不是本站的追踪，方框里的示例短语也不是你应该抄的标题。SEO 健康问的是：对你的 URL 的一次获取是否已经包含这种树：一个标题、一个标题元素，以及一条真实链接。

定义

解析把标签变成树。脚本随后可以追加、移动或删除节点，因此人在开发者工具里看到的 DOM 可以和源代码不同。保存响应的爬虫保存的是源代码。如果唯一的 h1 和唯一的产品链接是在解析之后才被创建的，它们就不在那份被保存的响应里。图已经把这些节点画在文档内部。这是你希望服务器发出的文件所具备的状态，而不是你希望后来的脚本去发明的状态。

渲染对爬虫意味着什么变化

把标题、标题元素和抓取路径上的链接放进一次获取所返回的源代码里。

把查看源代码，或不运行脚本的客户端，和实时的树作比较。如果图中的那些部分只存在于实时的树里，模板就把文档建得太晚了。链接节点需要源代码里的 href，而不是后来才加上的点击处理。抽样一条产品 URL。图里的短语是来源页上的占位符。它们不是测量，也不是推荐的标题。

要检查什么

  • 查看源代码中有 title、h1 和 href
  • 不运行脚本的获取仍然能看见它们
  • 链接是锚点，而不只是点击处理
  • 图中的示例短语没有被抄成标题
  • 一条产品 URL 同时按源代码和实时树作了比较

一个结构示例

产品名在开发者工具里显示为 h1，在查看源代码里却没有，因为节点是脚本创建的。修复是在服务器发送的 HTML 里渲染 h1 和锚点。第二次获取能看见标题和 href。图中的树仍然是关于 document、head 和 body 的教学图。它不是这条产品 URL 的截图。

它不声称什么

与树一致的源代码不保证排名或引用。
