短答

500 状态表示服务器在处理请求时失败，因此客户端没有收到文档。

其他 5xx 代码是同一族：失败的是站点，不是客户端。收到 500 的爬虫可能稍后重试，也可能放慢。SEO 健康把失败的模板当作该类型发现的中断。它不把失败解释成内容缺口。本页的终端截图是一次成功的交换：状态行写着 200。500 会出现在同一行上。本文不把截图里的日期或大小注释当作测量。

定义

当你知道中断是暂时的，带 Retry-After 头的 503 是礼貌的形式。单个坏模板上的 500 是缺陷，不是维护窗口。把 URL 抽样两次。如果它只在某个参数存在时失败，记下该参数。不要用 200 的空状态把失败藏起来。

抓取怎样遇到这条规则

修好返回 5xx 的模板或依赖，并确认稍后的获取返回文档。

间歇性的 500 需要一条样例和一个时间，而不是为审计编造的混合错误率。如果只有 PDF 生成器失败，就这么写，不要让 HTML 产品页跟着下线。发布一篇关于可靠性的博客并不会让获取成功。

要检查什么

  • 应该是文档的 URL 上的 5xx
  • 修复后的第二次获取
  • 空状态缺陷没有被变成 200 软错误
  • 失败的依赖被点名
  • 一条样例 URL 和状态

一个结构示例

/products/valve 返回 500，因为相关零件查询在列表为空时抛错。HTML 模板除此之外是好的。修复处理了空列表，第二次获取返回 200 和产品文字。相关零件区块可以不出现。文档不能没有。
