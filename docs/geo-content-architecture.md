# GEO 内容架构（知识中心）

> 约束文章 lane 撰写 GEO / 可引用性 / AI 搜索可见度类指南。  
> GEO = Generative Engine Optimization（生成式引擎优化）——面向回答系统与引用就绪，**不是**地理位置 SEO 的缩写（若文中提及需澄清）。

## 1. 目标

让公司、产品与主张在页面上：**定义清楚、短答可摘、证据可核、实体一致**——提升被理解与被引用的就绪度。  
**明确禁止：** 承诺「保证被 ChatGPT/Perplexity 引用」「保证 AI 排名」或任何回答面保底。

## 2. 适用 slug 族

- 定义与审计：`what-is-geo`、`how-to-audit-ai-search-visibility`、`what-makes-a-page-easier-to-reference`  
- 实体与信息：`how-to-make-company-information-clearer`、`how-to-structure-product-information`、`how-to-build-consistent-entity-information`  
- 问题与证据：`how-to-answer-buyer-questions-directly`、`how-to-build-evidence-around-product-claims`、`how-to-improve-citation-readiness`  
- 方法：`geo-health-vs-geo-growth`、`entity-evidence-answerability`、`question-coverage-for-websites`  
- 研究：`how-geo-handbooks-structure-source-backed-pages`、`how-source-backed-bilingual-sites-are-structured`

## 3. GEO 文章强制结构

每篇 GEO（及 GEO 方法）文必须包含以下可读区块（可用 H2，class 落在 `kc-body` 内）：

| 区块 | 要求 |
| --- | --- |
| **直接定义** | 开篇用白话定义主题（人与模型都能摘录） |
| **短答** | 2–5 句「可直接引用」的答案块，避免空话 |
| **解释** | 机制、适用边界、与 SEO Health/Growth 的关系 |
| **例子** | B2B 页面结构示例（公司/产品/规格/场景） |
| **来源** | `kc-sources`：可核验的公开来源或一手事实说明 |
| **FAQ** | `kc-faq`：买家会问的后续问题 |

推荐骨架：

1. 定义  
2. 短答（可单独成小节，便于摘录）  
3. 为何影响 AI/回答可见度（稳健表述）  
4. 如何做（步骤 / 清单）  
5. 例子  
6. 局限与合规（不保证引用）  
7. 来源 · FAQ · 相关阅读 · CTA

## 4. 写作禁区与允许表述

| 禁止 | 允许 |
| --- | --- |
| 保证引用 / 保证进回答摘要 | 「提高被正确理解与引用的就绪度」 |
| 保证某模型排名或曝光 | 「减少模糊表述与证据缺失」 |
| 编造客户案例、虚假认证 | 「用规格、流程、公开文档作证据」 |
| 与 SEO 文章近重复换皮 | 明确 GEO 视角：实体、可答性、证据 |

## 5. GEO Health vs GEO Growth

与首页框架一致：

- **GEO Health：** 实体清晰、主张有证据、关键问题有直接答案  
- **GEO Growth：** 尚未覆盖的问题、可扩展的引用就绪主题、多语言实体对齐空间  

文章应帮助读者区分「今天是否清楚」与「明天还能回答什么」，而不是打一个神秘 GEO 分数。

## 6. 内链

- GEO ↔ SEO 对照文（如 Health vs Growth 成对）  
- 链到开源研究：爬虫检查项、手册结构、双语有来源站点  
- 产品锚点：`/#geo`、`/#questions`、`/#entity`（中文对应 `/zh/`）

## 7. 元数据与页面 class

同 SEO 架构：独立 title/description/canonical/hreflang/OG；统一使用 `kc-page`、`kc-header`、`kc-nav`、`kc-hero`、`kc-meta`、`kc-layout`、`kc-toc`、`kc-body`、`kc-sources`、`kc-related`、`kc-faq`、`kc-cta`。
