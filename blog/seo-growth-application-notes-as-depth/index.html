Direct answer

An application note is depth when it adds a condition the product page did not have room to explain, using the same product name and the same limits. A second copy of the hero slogan is not a note.

Why it matters

Notes fail when they drift. A torque sequence that contradicts the datasheet is a new specification. Keep the note as a child of the product URL: link both ways with descriptive anchors. If the note answers a different question, it can be its own URL. If it repeats the product page, edit the product page instead.

What to check

State the setup, the step that matters, and the stop condition. Put numbers in HTML. Link the datasheet for the values you are not repeating in full. Mark the question partial if the note covers only one of several setups.

  • Use the same product name and limit as the product page.
  • Add a setup or exclusion that was missing.
  • Link both ways.
  • Do not contradict the datasheet.

A practical example

The product page states a maximum pressure. The note explains the order of valve opening and adds “do not exceed the page’s pressure.” It links the product URL. It does not introduce a higher pressure. No field-success rate is claimed.

Content depth

Depth is the added condition. Word count without that condition is padding. The figure may illustrate the setup. The sentence still has to be in text.

How an unanswered topic gets found

The product page should link the note with the name of the setup. The note should link back. Orphan notes do not deepen the product. Re-audit both URLs after publishing.
