Largest Contentful Paint Has Parts Before the Image Finishes

Largest Contentful Paint is not only the download of the hero image.

Short answer

Largest Contentful Paint is not only the download of the hero image.

The wait can start before the image request is even sent: the HTML response, discovery of the image URL, the transfer, and the paint after the bytes arrive. A health note that says only “compress the hero” misses the part that is actually long.

Definition

A breakdown diagram separates those stages so a team can see whether the document was late, the image was discovered late, the file was heavy, or the browser had the file and still waited to paint. Each stage suggests a different repair. None of the stages is a ranking factor this page is allowed to promise.

How the definition is used in a health pass

Record which subpart dominates on the sample URL, and do not replace that observation with a single made-up millisecond total.

If the HTML itself is slow, image compression will not move the start of the timeline. If the image URL is injected by a script after load, the crawler and the browser both discover it late. If the file is large and discovered immediately, then weight and format are the relevant health notes. The diagram is a map of stages, not a report card for a domain.

What to check

  • Whether the HTML response is late before any image request
  • Whether the hero URL is in the initial HTML
  • Whether the hero is lazy-loaded even though it is in the first viewport
  • Whether render is blocked after the bytes have arrived
  • One sample product URL beside the dominant stage

A practical example

A pump configurator sends a light HTML shell, then a script requests the product render. The largest element is that render. The long stage is discovery, not the final compression of a file the browser has not been told about. The health action is to name the image in the first HTML or to stop treating the hero as a below-the-fold asset.

What this does not claim

Splitting LCP into stages does not guarantee rankings or a faster indexation outcome.
