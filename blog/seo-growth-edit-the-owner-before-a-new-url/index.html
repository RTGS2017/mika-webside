Direct answer

If a URL already owns the subject, edit that URL so the missing answer is in its HTML. Create a new URL only when the question is a different job with its own fact and its own internal links. Another slogan page is not growth.

Why it matters

Page count is not SEO growth. Near-duplicates and thin template collisions are a duplicate-content problem. The health response and the growth response can agree: keep the real document. Growth adds the uncovered sentence. It does not celebrate the extra address.

What to check

Search the site for the subject before you open a new brief. If the answer is partial, write the missing constraint on that page. If you still need a new URL, say why the old one cannot hold the job. Plan redirects later only if you retire a true duplicate.

  • Find the existing owner before creating a URL.
  • Add the missing sentence there when the job is the same.
  • Retire true duplicates instead of feeding them.
  • Point internal links at the owner.

A practical example

Three blog posts promise to explain the same flange standard and none quotes the pressure class. The repair adds the class to the one post that already names the standard and noindexes or redirects the empty copies after the sentence exists. No content score is claimed.

Content depth

The edited page is deep enough when the new sentence answers the question. Moving the same sentence into a new URL does not add depth.

How an unanswered topic gets found

Update the internal links so they point at the owner with a descriptive anchor. Drop empty URLs from the sitemap. Re-audit the owner and confirm the copies no longer contradict it.

Growth is the answer on the owner, not the birth of another address. Mika Visibility files this on the SEO Growth track: coverage, intent depth, and markets that are still open. It is not an SEO Health score and it is not GEO. Page count is not growth. There is no blended overall score.

What this does not claim

Editing the owner does not guarantee rankings or AI citations. More URLs are not coverage.
