Dynamic Rendering Was a Workaround That Served Different HTML to Crawlers

Dynamic rendering serves the JavaScript application to browsers and a separate HTML snapshot to crawlers.

Short answer

Dynamic rendering serves the JavaScript application to browsers and a separate HTML snapshot to crawlers.

The diagram shows that split. The snapshot can be stale, thinner, or simply different from what people see. SEO Health treats that difference as a defect to retire, not as a feature to extend. The preferred repair is one HTML response that already contains the content, for both.

Definition

Cloaking is the uncomfortable neighbor: showing crawlers something people are not shown in order to manipulate. Dynamic rendering was documented as a workaround for shells, not as a way to show a keyword page to a crawler and a different offer to a buyer. If the snapshot and the app diverge, you no longer know which document you are maintaining.

What rendering changes for a crawler

Retire the separate snapshot and serve the same primary HTML to browsers and crawlers.

While the workaround still exists, the audit should diff the snapshot against the rendered app on a sample URL and record every missing specification or link. A snapshot that omits prices or adds lines the app does not show is not a neutral performance trick. Re-audit after the template serves one document.

What to check

  • Whether crawlers and browsers receive the same primary facts
  • A diff of snapshot versus app on one URL
  • Missing specs or extra lines called out
  • A plan to serve one HTML source
  • No extra keyword text that exists only in the snapshot

A practical example

A parts site snapshots HTML nightly for crawlers and ships a live app to browsers. A specification changed in the app at noon and the snapshot still has yesterday’s value. The health finding is the drift. The repair is server HTML from the same source the app uses, not a faster snapshot job.

What this does not claim

Dynamic rendering does not guarantee rankings or citations.

Where Mika Visibility files this
