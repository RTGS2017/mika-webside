URL Normalization Picks One Spelling for One Document

URL normalization chooses one spelling of a document and treats the other spellings as duplicates.

Short answer

URL normalization chooses one spelling of a document and treats the other spellings as duplicates.

Letter case on the host, a trailing slash, index.html versus the directory, and percent-encoding of characters that did not need it are common variants. SEO Health picks the canonical spelling, redirects the others with one hop, and uses only the chosen spelling in links, the sitemap, and the canonical element.

Definition

Normalization is not the same decision as which parameters are identity. That is the query-string note. Here the path and host are the subject. A canonical tag that points at a spelling which itself redirects is a chain. Make the tag, the sitemap, and the redirect target the same URL.

How this affects the indexable URL

Redirect every alternate spelling to one canonical URL in a single hop, and link only to that URL.

Choose the slash policy and keep it. Mixing /pumps and /pumps/ as if they were both canonical splits signals. Default documents such as index.html should redirect to the directory URL you chose, or the reverse, but not both as 200s. The sample is a pair of URLs and their status codes.

What to check

  • One host, scheme, and slash form
  • index.html or the directory, not both as 200
  • Canonical, sitemap, and redirects naming the same URL
  • Internal links already using that URL
  • A sample pair with status codes

A practical example

Links and the sitemap use https://www.example.com/pumps/index.html while the canonical tag points at https://example.com/pumps. Both return 200. The repair 301s the www and index.html forms to the chosen URL, updates links and the sitemap, and makes the canonical tag name that same URL.

What this does not claim

Normalization does not guarantee rankings or citations.
