Client-Side Script Can Build Nodes the Source Never Had

Client-side script runs in the browser and can create elements that were not in the fetched HTML.

Short answer

Client-side script runs in the browser and can create elements that were not in the fetched HTML.

The listing creates a div, creates a list, and appends items whose text is computed in the browser. Those items are not written in the HTML of the example. They appear only after the script runs. SEO Health treats that pattern as a risk when the items are the product list, the specification, or the links to other documents. The weekday-style computation in the listing is an example from the source page. It is not a feature to install, and it is not a locale report.

Definition

A script may enhance a list that is already in the HTML, for example by sorting nodes that the server already sent. A script may also be the only author of the list. The second case fails a fetch. Progressive enhancement keeps the list in the source and lets the script rearrange it. The listing on this page is the second case: the list items are created and appended. Use it as a picture of the risk, not as code to paste into a template.

What rendering changes for a crawler

Keep the list a crawler should see in the HTML, and let script enhance it rather than invent it.

Fetch the URL and search the source for the product names. If they exist only inside a script that builds elements, they are not yet a document. A noscript note that says “enable JavaScript” is not a substitute for the list. Compare one URL with the script blocked. The listing’s loop is an illustration of create-and-append. Do not copy it, and do not describe its numbers as a result.

What to check

  • Product or model names present in the fetched HTML
  • Script that enhances that list rather than creating the only copy
  • A noscript message not used as the only content
  • One URL fetched with script blocked
  • The example listing not pasted into the template

A practical example

A family page’s model list is empty in the HTML and is filled by a script that creates one item per model. The repair renders the models as list items on the server and lets the script only mark the current one. A fetch without script shows the names. The source listing stays an example of the opposite pattern.

What this does not claim

Client-side script does not guarantee rankings or citations.

Where Mika Visibility files this

The listing shows nodes being created in the browser. The audit looks for those nodes in the HTML instead.
