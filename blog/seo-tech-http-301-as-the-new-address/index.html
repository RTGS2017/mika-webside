Short answer

A 301 response tells a crawler that this URL has moved and that the Location target is the address to fetch. Use it when one canonical document replaced the old URL, and make that target return the subject’s text.

Definition

Redirects are part of the crawl path. A 301 that lands on a soft error, a homepage, or a chain of further redirects wastes the path. The useful pattern is one hop to the URL you want indexed. Keep the new document’s title and primary text about the same subject, or the redirect preserves an address while losing the page. Query copies and session URLs should not become extra 301 targets.

What belongs on the page

Fetch the old URL and read the status and the Location header. Then fetch the target and confirm it is the canonical you intend, with a self-referencing canonical. Update internal links so people and crawlers are not sent through the old address forever. The sitemap should list the new URL.

What to check

  • One hop from the retired URL to the replacement.
  • The target returns the subject’s title and text.
  • Internal links use the new URL.
  • The sitemap lists the target, not the retired address.

A practical example

A retired alloy page 301s to the family page that never names that alloy. The repair either 301s to a URL whose HTML states that alloy’s range, or keeps one document that contains the range and redirects the old address there. Re-audit the hop. This is not a ranking method.
