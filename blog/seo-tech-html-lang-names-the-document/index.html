The lang attribute should name the language of the document

The lang attribute on the html element names the language of this document. Set it to the language of the body you publish. On this site that is en for English URLs and zh-Hans for Chinese URLs. It does not replace hreflang.

Short answer

The lang attribute on the html element names the language of this document. Set it to the language of the body you publish. On this site that is en for English URLs and zh-Hans for Chinese URLs. It does not replace hreflang.

Definition

Language metadata helps a reader and a parser know which language the words are in. If the attribute says English and the body is Chinese, the document disagrees with itself. Hreflang relates two URLs. lang describes the one document that was fetched. A template that stamps en on every language path is a template defect. Do not add an /en/ prefix to “match” the attribute.

What belongs on the page

View the source of the canonical URL and read the html tag. Compare it with the H1 and the first paragraph. Then check the alternate URL. The two documents should name their own languages and point at each other with hreflang, including x-default on English.

What to check

  • lang matches the body language of that URL.
  • English and Chinese documents do not share one lang value.
  • hreflang still names the alternates.
  • The attribute is fixed in the template, not on one page only.

A practical example

A Chinese product path is served with lang equals en because the shell was copied. The repair sets zh-Hans on that template and leaves en on the English document. The specification text is unchanged by the attribute. No language-detection score is claimed.

What this does not claim

A correct lang attribute does not guarantee rankings or AI citations. Mika does not treat language tags as market share.
