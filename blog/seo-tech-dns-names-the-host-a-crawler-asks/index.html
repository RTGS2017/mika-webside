DNS has to resolve the hostname you publish

Short answer

DNS resolves the hostname in your URLs to an address a client can connect to. If the canonical host does not resolve, there is no fetch and no document. Fix the name before you debate titles.

Definition

Hostnames are part of the URL. www and apex hosts that both answer should agree on which one is canonical, usually with a redirect to the single host you publish. A hostname that resolves only inside a private network is not a public document. Internationalized names have to work as the URL you actually advertise. SEO Health includes whether the live URL can be fetched. It does not score the registrar.

What belongs on the page

Resolve the host on the canonical URL and fetch it. If two hosts return the same HTML without a canonical agreement, pick one and redirect the other. Check that a change of name server did not drop the record for the host you print in hreflang and in the sitemap.

What to check

  • Resolve the canonical hostname from a public resolver.
  • Fetch that host and read the document.
  • Canonicalize www and apex to one host.
  • Keep sitemap and hreflang on the host that resolves.

A practical example

After a DNS cutover, the host in the sitemap no longer resolves, while a temporary host serves the pages. The repair restores the published hostname, 301s any temporary host to it, and re-fetches the canonicals. No uptime percentage is invented.
