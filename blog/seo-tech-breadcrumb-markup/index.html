Breadcrumb Markup Repeats the Trail the Page Already Shows

Short answer

Breadcrumb markup lists the trail of pages that the visible breadcrumb already shows.

The result illustration shows a trail in a search presentation. That is an eligibility example, not a placement this page promises. If the JSON-LD skips a level or invents a category the menu does not have, the markup describes a site that is not the site. SEO Health makes the list match the anchors.

Definition

Each list item needs a name and, except sometimes the current page, a URL that is the canonical URL of that level. Linking the crumb to a filtered duplicate sends both people and the markup at the wrong identity. The visible trail is also an internal link path, so a crumb that is text without an anchor fails navigation even if the JSON-LD is perfect.

What the markup can and cannot do

Match each markup item to a visible anchor and to that level’s canonical URL.

Do not generate breadcrumbs from the URL path if the path is an implementation detail that does not match the information architecture. A /node/184 URL with a generated crumb “node / 184” is noise. The trail should be the names buyers use: products, then the family, then the item.

What to check

  • Markup items aligned with visible anchors
  • Canonical URLs on each level
  • No crumbs generated from meaningless path segments
  • The current page not linked as if it were a different URL
  • One product URL where both trails were read

A practical example

A product page shows Home / Valves / Gate valves / DN50, but the markup lists Home / Blog / DN50. The repair rewrites the JSON-LD from the same data that renders the visible trail, using canonical URLs. The search illustration is not the success criterion. The match is.

What this does not claim

Breadcrumb markup does not guarantee rankings or a trail in results.
