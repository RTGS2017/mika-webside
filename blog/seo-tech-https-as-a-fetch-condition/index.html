HTTPS Is the Fetch You Want Browsers and Crawlers to Use

Short answer

HTTPS should be the scheme of the canonical URL, with HTTP redirecting to it in one hop.

The panel in the figure is a browser saying one particular connection is secure and naming that certificate’s holder. That is a transport fact about the site in the screenshot. It is not a ranking trophy and not a certificate of content quality for anyone else. SEO Health cares that one scheme is canonical, that the other redirects, and that the page does not pull scripts or images over the scheme you just left.

Definition

Mixed content is an HTTPS page that still requests an HTTP asset. Browsers may block that asset. A blocked stylesheet or script can remove the layout or the behavior people need, and a blocked image can remove the hero. The certificate’s marketing badges are irrelevant to that check. Look at the requests.

How a crawl meets this rule

Redirect HTTP to the HTTPS canonical in one hop, and remove HTTP asset URLs from the page.

Canonical tags, sitemaps, and internal links should already use https. A redirect that bounces through a www host and a trailing-slash change is three hops. Collapse them. HSTS can tell browsers to remember the scheme. It does not fix links you still print as http in the HTML.

What to check

  • One HTTPS canonical host
  • HTTP page URLs redirect in one hop
  • No HTTP images, scripts, or PDFs on the HTTPS page
  • Sitemap and internal links already https
  • One product URL’s requests checked

A practical example

The sitemap lists https URLs, but the product template’s PDF links are http and the hero image is http. The page is HTTPS and the assets are blocked or warned. The repair changes the asset URLs and keeps a single redirect from any http page URL. No badge is added to the audit.

What this does not claim

HTTPS does not guarantee rankings or citations.
