The canonical link should name the URL you want indexed

Short answer

A canonical link names the preferred URL for a document that may be reachable by more than one address. Point it at the URL whose HTML states the subject, and make that URL self-canonical. It does not merge two different products into one.

Definition

Duplicates come from parameters, trailing-slash variants, printable copies, and templates. The canonical is a hint about which URL is the document. If it points at a URL that 404s, redirects, or discusses a different subject, the hint is noise. Hreflang alternates should be canonicals too. Do not canonicalize every language to English when each language is its own document with the same facts.

What belongs on the page

Fetch the URL, read the canonical, and fetch that target. Confirm one subject, one preferred URL, and internal links that use it. Parameter URLs that only reorder a list can point at the clean document. Parameter URLs that change the product should be their own documents or they should not exist.

What to check

  • The preferred URL returns 200 and names itself as canonical.
  • The canonical target discusses the same subject.
  • Language URLs do not collapse onto one language.
  • Internal links prefer the canonical.

A practical example

Every finish variant canonicals to the uncoated product, so the coated range never has a URL. The repair gives the coated range its own document and a self-canonical, or states both ranges in one document and stops publishing the empty variant URLs. Re-audit. No consolidation bonus is claimed.

What this does not claim
