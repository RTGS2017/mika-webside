Preload Is for a Resource the First Screen Will Need Immediately

Short answer

Preload tells the browser to fetch a specific file early because the first screen needs it.

The network panel is how you see whether that request moved earlier. Preload is a hint in the document head, with a URL the server already knows. It is not a way to discover an image that script will invent later. SEO Health checks that the hinted URL is the one the first viewport actually uses.

Definition

A preload for a font or hero that is not used on that template competes with the files that are used. Hints are not free. The audit looks for a small number of preloads that match the template, not a copied head from another layout. A screenshot of a network panel in documentation is an illustration of the tool. It is not this site’s trace.

What rendering changes for a crawler

Preload only the hero or font this template uses in the first viewport, and confirm the URL exists in the initial HTML.

If the hero URL is chosen by client script from an API, a preload in the head cannot name it yet. The health fix is to print the URL into the HTML, then hint it, not to preload a placeholder. After the change, one sample URL’s network list should show the hero starting without waiting for a late discovery. Do not paste another site’s waterfall into the report.

What to check

  • Preload URLs that match files the first screen uses
  • Unused preloads copied from another template
  • Hero URLs that are not yet in the HTML, so they cannot be hinted
  • One sample URL after the hint list is edited
  • No foreign waterfall treated as local evidence

A practical example

A landing template preloads three campaign fonts and a video poster it never shows, and does not preload the actual product cutout. The cutout is injected later. The note says: remove the unused hints, print the cutout URL, hint that one file. The campaign fonts can load with the pages that use them.

What this does not claim

A correct preload does not guarantee rankings or citations.
