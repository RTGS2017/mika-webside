# Mika 开源研究源流水线

本目录是**研究源登记与待复核清单**，不是自动发文机。

目标：从公开开源仓库收集可核验的设计事实，写成 Mika 原创 Research Note，并保留可见署名。绝不把 README 正文、整仓克隆或批量抓取结果直接塞进站点。

## 流水线（人工闸门）

1. **仓库** — 在 `sources.json` 登记公开仓库身份、许可证、源 URL、查看日期。
2. **收集事实** — 只记录可观察的设计事实（检查什么、如何组织内容、有哪些公开产物）。不存 README 全文。
3. **主题** — 选定一个可独立回答的主题（一个问题、一篇简报、一篇文章）。
4. **原创简报** — 用自己的话整理观察与对审计工作的启发。
5. **Mika 原创文章** — 写成双语 Knowledge 文章；英文约 500–800 词；不粘贴源仓库正文或大段代码。
6. **来源署名** — 页面必须有可见来源面板：仓库名、作者、许可证、源链接、查看日期。MIT 只做事实归因；CC BY-SA 需正确署名并标明受启发表述以相同许可证分享。
7. **人工复核** — 核对事实、许可证措辞、是否避免保证引用/排名承诺、是否落入低价值批量内容。
8. **发布** — 仅在人工通过后纳入站点发布流程。

## 明确禁止

- **禁止** README / 文档直译发布。
- **禁止** 批量抓取后自动生成大量页面。
- **禁止** 拼接多个仓库内容去“填页数”。
- **禁止** 把整仓克隆进本静态站。
- **禁止** 自动改写并自动发布。

Google 将以操纵排名为主要目的的批量低价值内容视为风险。研究源存在的意义是支撑少量、可核验、有署名的原创笔记，而不是制造页面密度。

## 更新机制

更新只做成：**发现仓库变化后生成待复核候选**。

- 人工或外部流程可更新 `sources.json` 中的 `last_known_pushed_at` / `pending_review`。
- `list-updates.mjs` 只读本地 `sources.json`，打印待复核项。
- **不联网抓取**，**不写网站页面**，**不自动改写文章**。

## 本地脚本

```bash
node tools/research/list-updates.mjs
```

无第三方依赖。输出仍为待复核候选列表，下一步永远是人工。
